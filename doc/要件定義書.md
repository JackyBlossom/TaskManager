# 工程管理アプリ 要件定義書

作成日: 2026-07-04
作成元: `reference/工程管理_素案.xlsx`（企画メモ）を整理

---

## 1. 概要

**コンセプト: 「簡単操作で楽々プロジェクト管理」**

プロジェクト・タスクの計画/進捗/実績を、ガントチャートを中心に一元管理するWebアプリケーション。
プロジェクト管理者だけでなく、現場作業者やPC操作に不慣れなメンバーも含めて、組織全体の「工程」を見える化することを目指す。

管理対象は大きく2つ。

| 用語 | 定義 |
|---|---|
| タスク | プロジェクト完了のために必要な作業項目 |
| 業務 | 作業者に割り当てられた具体的な作業 |

> 注記: 企画メモでは「タスク」と「業務」を区別しているが、データ構造上はどちらも同じ Task エンティティ（[8章](#8-データ項目概要)）で表現する。本書では以降「タスク」に統一して表記する。

---

## 2. 誰が使うか（想定ユーザー）

| ユーザー | 主な利用目的 |
|---|---|
| プロジェクト管理者／現場監督 | プロジェクト・タスクの登録、全体ガントチャートでの進捗確認、メンバーの負荷把握、作業指示書の展開 |
| プロジェクトメンバー／作業者 | 自分に割り当てられたタスクの確認（個人ガントチャート／ToDoリスト）、進捗・実績の報告 |
| PC操作に不慣れな作業者・現場作業員 | 印刷された作業指示書で当日の作業内容を確認し、実績を報告 |
| 一般部署の担当者（例: 経理など） | ITプロジェクトに限らない日常業務のタスク・スケジュールをExcelのガントチャート代わりに管理 |
| システム管理者 | プロジェクト／ユーザー／組織などのマスタ管理 |

> 補足: 経理部門でもExcelガントチャート（タスク名・担当者・期限を管理する簡易表）でタスク管理をしている実態があり、IT系プロジェクト以外の一般業務でも使える汎用性を持たせたい。

---

## 3. 何のために使うか（目的）

- プロジェクトの全体進捗と個人の作業状況を、誰でも直感的に把握できるようにする。
- タスクの登録から進捗管理、実績報告までを一つのツールで完結させ、Excel管理や口頭確認による工数・伝達ミスを減らす。
- メンバーごとの負荷（余裕/逼迫）を可視化し、業務の偏りを早期に発見・支援できるようにする。

> 補足: 「PCを持たない/使い慣れない現場作業者にも紙の作業指示書で作業内容を伝達する」という目的も企画メモにはあるが、これは[6.2 次フェーズ検討](#62-次フェーズ検討優先度-中-として記載されていたもの)の機能に対応するものであり、MVPの目的からは切り離す。次フェーズ着手時にあらためて目的として明記する。

---

## 4. どんな場面で使うか（利用シーン）

1. **プロジェクト立ち上げ時**: 過去のプロジェクトやテンプレート（雛形）から複製し、タスクを登録する。
2. **日々の業務**: 各メンバーが個人ガントチャート／ToDoリストで自分のタスクを確認し、状況（未着手／対応中／問題発生中／完了）を更新する。
3. **進捗会議・管理業務**: 管理者が全体ガントチャートやダッシュボードで遅延・課題を確認し、必要に応じてタスクの担当者や期日を調整する。
4. **現場作業**（※次フェーズ機能を含む）: 作業指示書を印刷・展開し、PCを使わない作業者へ当日の作業を指示。作業後は実績報告（写真添付含む）を行い、承認されると進捗に自動反映される。
5. **要員負荷調整**: 負荷が高いメンバーがSOSを発信、または管理者が可視化された負荷状況（青/黄/赤）を見て応援を割り当てる。
6. **振り返り・見積り**: 過去プロジェクトのガントチャートや工数実績を参照し、類似案件の見積りに活用する。

## 5. 成功の定義（何ができれば成功か）

MVP（最小構成）として、以下ができれば「使える工程管理アプリ」として成功とする。

- [ ] プロジェクトとタスクを登録・更新・削除でき、全体ガントチャートで一覧できる。
- [ ] タスクの詳細（名称・期間・担当者・状態・内容など）を確認・編集できる。
- [ ] タスク状態や期日変更が、全体ガントチャートに即時反映される。
- [ ] 担当者ごとの個人ガントチャート／ToDoリストで、自分のタスクを確認できる。
- [ ] タスク期限が近い／超過した場合に通知が届く。
- [ ] タスクの進捗率が視覚的に分かる（%表示、完了/未完了の識別）。
- [ ] タスク同士の依存関係（関連線）を設定できる。
- [ ] 予定と実績の工数を入力・集計できる。
- [ ] ダッシュボードで進捗状況・遅延件数・課題状況を俯瞰できる。
- [ ] プロジェクト／ユーザー／組織のマスタ管理ができる。

加えて、機能の実装有無だけでなく、以下の利用者側の成果が確認できることを成功の目安とする。

- [ ] これまでExcelや口頭で行っていた進捗確認・共有の手間が減ったとユーザーが実感できる。
- [ ] 管理者が全体ガントチャート／ダッシュボードを見るだけで、遅延や停滞しているタスクに気づける。
- [ ] IT系プロジェクト以外の一般部署（経理など）でも、シンプルなタスク・スケジュール管理として使える。

上記に加え、優先度「中」以下の機能（後述）は将来フェーズでの拡張候補とする。

## 6. スコープ

### 6.1 MVPスコープ（優先度: 高）

- 全体ガントチャート（タスクCRUD、進捗表示、詳細表示、関連線、いなずま線、表示切替、マイルストーン、ファイル出力、通知、検索/絞り込み、過去PJ複製）
- 個人ガントチャート（自分のタスク確認、他メンバー参照、負荷の視覚化）
- ToDoリスト（ガントチャートとの表示切替、実績把握、期限アラート）
- 工数管理（予実績入力、原価集計）
- リマインド（期限通知）
- マスタ管理（プロジェクト／ユーザー／組織）
- ダッシュボード（進捗・遅延・課題の可視化）
- 課題管理表

### 6.2 次フェーズ検討（優先度: 中 として記載されていたもの）

- スマホ/タブレット対応（現場写真添付、手書きメモ）
- 業務指示書作成・実績報告（PC非利用者向け、フォーマット選択、PDF/印刷出力）
- ショートカットキー操作
- クリティカルパス／PERT図（アローダイアグラム）作成
- 作業タイプ管理（定型作業セットの選択）
- 作業届（フォーマット取込・作成・出力）

### 6.3 将来検討・別枠対応（今回は対象外）

- 会議支援（別枠で検討）
- 資料共有・資料管理（外部リンクで対応、ファイル管理機能は持たない）
- 過去プロジェクトの数値管理（見積り支援）
- 他システム連携（チャットツール連携、SSO、社内商材連携）
- カレンダー連携（Google/Outlook/Teams）
- 進捗のエンターテインメント表現（建物オブジェクトでの進捗表現等）
- 福利厚生連携（社内ポイント制度連携）
- 貢献度の見える化（重み付け評価、ありがとうボタン）
- MRP
- プロジェクト内の複数案件管理
- 相談所機能（メンタル/人間関係分析）
- タスクのレコメンド（AI活用）

## 7. 機能要件

### 7.1 全体ガントチャート

| 小項目 | 説明 |
|---|---|
| タスク登録・更新・削除・完了 | タスクとその属性（名称・期間・ステータス等）をCRUD |
| 組織選択 | 組織（部/課/ユニット等）をプルダウンで選択し、参照範囲を絞り込む |
| プロジェクト雛形 | タスクのパターンをテンプレート化し、必要に応じて編集可能にする |
| 進捗管理 | 完了率を表示。点線・網掛け等で視覚的に表現 |
| 詳細タスク確認 | ガントチャートのバーをダブルクリックしてタスク詳細を表示・編集。項目: タスク名／期日（変更するとガントチャートに反映）／完了条件／担当者（変更可）／内容／状況（未着手・対応中・問題発生中・完了、初期値は未着手）／進行状況（晴れ・曇り・雨）／課題／メモ／チャット／ワークフロー／前後タスクへの引き継ぎ情報 |
| 工数管理連携 | 納期と作業項目を入力すると、ガントチャートを自動生成 |
| 関連線（依存関係） | タスク間の前後関係を手動または属性に基づき自動で設定。ボトルネック特定にも活用 |
| いなずま線 | 日付指定とON/OFF操作で進捗を一目で確認できる線を表示 |
| チャート操作 | ドラッグ＆ドロップでスケジュール調整 |
| 表示レベル切替 | プロジェクト／タスクの階層レベルを選んで表示（大タスクのみ表示等） |
| 表示期間切替 | 月／週／日単位でスケジュール表示を切替 |
| マイルストーン | 顧客レビュー日程・リリース日等の登録 |
| ファイル出力 | PDF／Excel／CSV形式で出力 |
| ダッシュボード | 進捗率、遅延タスク件数、課題消化率等をグラフ表示 |
| 課題管理表 | 各タスクの課題を集約した一覧を生成・出力 |
| 通知 | 期限接近／超過／完了時に通知（チャットツール連携、ログイン時ポップアップ） |
| タスク検索・絞り込み | 検索結果をガントチャート上で視覚的に強調表示 |
| 過去PJ複製 | 新規プロジェクト登録時に過去プロジェクトを複製 |

### 7.2 個人ガントチャート

| 小項目 | 説明 |
|---|---|
| 自分のタスク確認 | どのプロジェクトでどのタスクが割り当てられているかを確認 |
| タスク登録・更新・削除 | タスクと属性（名称・期間等）のCRUD |
| 個人表示切替 | 個人名を選択して表示を切替（他メンバーの個人ガントチャートも閲覧可能とする想定だが、閲覧できる範囲は権限モデル未確定のため変更の可能性あり。[12章](#12-未確定事項今後の検討ポイント)参照） |
| メンバー一覧 | 参照したいメンバーを選択するための一覧 |
| 負荷の視覚化 | 顔写真付近に負荷状況を色分け表示（青: 問題なし／黄: やや負荷／赤: 高負荷）、継続期間も表現 |

### 7.3 ToDoリスト

| 小項目 | 説明 |
|---|---|
| 表示切替 | ガントチャート表示とToDoリスト表示を切替 |
| タスク登録・更新・削除 | タスクと属性（名称・期間等）のCRUD |
| 表示対象切替 | 個人名／プロジェクト名で表示対象を切替 |
| 予定表示 | 指定日／指定期間の自分の作業予定を一覧表示 |
| 作業実績把握 | 計画と実績の差分を表示 |
| 期限切れアラート | 期限切れタスクを強調表示 |

### 7.4 工数管理

| 小項目 | 説明 |
|---|---|
| 予実績入力 | プロジェクト／タスク単位で予定・実績工数を入力（人単位、代理入力可） |
| 原価管理 | プロジェクト・タスク・人単位で原価を集計 |

### 7.5 リマインド

- タスク期限接近／超過／完了時に通知。チャットツール連携またはログイン時ポップアップ通知。

### 7.6 マスタ管理

| 小項目 | 説明 |
|---|---|
| プロジェクト管理 | プロジェクト名・開始終了予定日等の基本情報をCRUD（CSV取込対応） |
| ユーザー管理 | システム利用者の管理 |
| 組織管理 | 全体ガントチャート／ダッシュボードの絞り込みに使用する組織情報の管理 |

### 7.7 次フェーズ機能（詳細は次フェーズ設計時に確定）

- スマホ／タブレット対応（同等操作、写真証跡添付、手書きメモ）
- 業務指示書作成／実績報告（フォーマット選択、PDF/印刷出力、承認による進捗自動反映）
- クリティカルパス／PERT図作成
- 作業タイプ管理
- 作業届（フォーマット取込・作成・出力）
- ショートカットキー操作

## 8. データ項目（概要）

Excelメモに記載されていた主要エンティティと項目案。詳細設計時にDB設計へ落とし込む。

| エンティティ | 主な項目 |
|---|---|
| Task（タスク） | uuid, name, level, upper（親タスク参照）, process（工程参照）, plannedstartdate, plannedenddate, startdate（実績）, enddate（実績）, personincharge（担当者参照）, status, progressrate |
| Project（プロジェクト） | uuid, name, plannedstartdate, plannedenddate, member（メンバー参照・複数選択） |
| Process（工程） | uuid, name, project（参照） |
| Workrecord（作業実績） | taskname, date, actualmanhour |
| User（ユーザー） | uuid, name, department |
| Issue（課題）※追加 | uuid, task（参照）, title, content, status, personincharge（参照）, duedate |
| Organization（組織）※追加 | uuid, name, parent（親組織参照、部/課/ユニット等の階層表現）, member（参照・複数選択） |
| TaskDependency（タスク関連線）※追加 | predecessortask（先行タスク参照）, successortask（後続タスク参照）, type（手動／自動） |

> **Task.upper と Process の関係について（要整理）**: 現状 Task には親タスク参照（upper、階層構造）と工程参照（process）の2種類の階層表現が併存している。「ガントパターン」シートの「要件定義→AAAAA/BBBBB…」のような大項目/小項目構造をどちらで表現するか（Process を工程の大分類とし、Task.upper はその配下の親子タスク構造とする、など）を詳細設計までに決定する。
>
> Issue／Organization／TaskDependency は7章の機能要件（課題管理表、組織選択・組織管理、関連線）に対応するエンティティが8章に存在していなかったため追加。マイルストーン・通知・タスクチャット・ワークフローについては、次フェーズ以降の詳細設計時にあわせてエンティティ化する（[12章](#12-未確定事項今後の検討ポイント)参照）。

## 10. 非機能要件

| 分類 | 要件 |
|---|---|
| ユーザビリティ | PC操作に不慣れなユーザーでも直感的に使える操作性（ドラッグ＆ドロップ、シンプルな画面構成）。将来的にスマホ／タブレットでも同等操作を可能にする。 |
| 認証 | ログイン画面を持つため、最低限ID／パスワードによる認証を必須とする。SSO（Google/MS）は[6.3](#63-将来検討別枠対応今回は対象外)の通り将来対応とし、MVPでは自前の認証方式を採用する。 |
| 権限管理 | 組織・プロジェクト単位での参照範囲制御が必要（他人の個人ガントチャート閲覧、組織選択による絞り込み等）。ロールベースか組織階層ベースかを含め、詳細は今後要検討（[12章](#12-未確定事項今後の検討ポイント)）。 |
| セキュリティ | ユーザーデータ・工数実績等の業務情報を扱うため、通信の暗号化（HTTPS）、パスワードの安全な保管、主要な操作（登録・変更・削除・承認）の証跡（監査ログ）を残すことを基本方針とする。 |
| 通知 | 期限接近・超過・完了等を通知する。許容遅延（例: 数分以内）や配信方式（ポーリング／WebSocket／プッシュ通知等）は次フェーズの設計時に確定する。 |
| データ出力 | ガントチャート・課題管理表・作業指示書等をPDF／Excel／CSVで出力可能にする。出力レイアウト・テンプレート仕様は詳細設計時に確定する。 |
| 可用性・バックアップ | 業務で日常的に利用するツールとなるため、定期的なデータバックアップ・復旧手順を用意する。目標稼働率・バックアップ頻度は今後の運用方針に合わせて確定する。 |
| 想定規模 | 同時利用ユーザー数、プロジェクト数、1プロジェクトあたりのタスク数の想定規模は未確定。設計判断（一覧表示の仮想スクロール要否等）に必要なため、詳細設計前に目安値を決める。 |
| 拡張性 | 将来的な他システム連携（チャットツール、カレンダー、SSO等）を見据え、疎結合な構成にする。 |
| パフォーマンス | 大規模プロジェクト（多数タスク・多階層）でもガントチャート操作がストレスなく行えること。具体的な数値目標（例: タスク件数◯件時の描画時間）は[想定規模]確定後に定める。 |

## 11. 参考: 業界別の追加要件（将来のカスタマイズ検討材料）

Excelメモには建設業を中心とした業界別ニーズの深掘りがあり、業種別カスタマイズの検討材料として記録しておく（今回のスコープには含めない）。

- **建設業**: 工程表作成、資材管理、安全管理、進捗状況報告。受注（顧客管理・見積・提案・契約）→設計（図面・仕様書・積算・安全計画）→施工（工程表・資材発注・写真動画UP・進捗報告）→検査（検査項目・結果記録・是正処置）→引き渡し（完成書類・引き渡し・アフターサービス）の各フェーズと、現場監督／施工業者／発注者／設計者／検査員といった立場ごとに異なる機能ニーズがある。
- **医療**: 患者情報管理、カルテ管理、診療予約、検査結果管理
- **教育**: 授業計画作成、教材管理、成績管理、生徒管理

## 12. 未確定事項（今後の検討ポイント）

設計着手前に決めるべき優先度で並べる。

### 優先度: 高（DB／API設計のブロッカーになるため要件定義段階で決める）

- タスクステータス／進捗率を、ユーザーが手動設定する方式にするか、下位タスクの完了数から自動算出する方式にするかの仕様。
- 権限モデルの方針（ロールベースか組織階層ベースか）。個人ガントチャートの他人参照範囲、組織選択による絞り込み範囲に直結する。
- Task.upper（親子タスク階層）と Process（工程）の関係の整理（[8章](#8-データ項目概要)参照）。

### 優先度: 中（詳細設計時までに決める）

- タスクへのファイル添付要否（メモには「ディスク管理が必要になるため慎重に」との記載あり）。
- プロジェクトに紐づかない単独タスクの扱い。
- 「工数管理連携（納期・作業項目からのガントチャート自動生成）」の詳細ロジック（依存関係・稼働カレンダーの考慮有無等）。
- ファイル出力（PDF／Excel／CSV、作業指示書等）のレイアウト・テンプレート仕様。
- 経理部門のような軽量ユーザー向けに、簡易表示モード（シンプルなタスク名・担当者・期限のみのガントチャート）を用意するか。

### 優先度: 低（次フェーズ着手時に検討）

- 通知の許容遅延・配信方式（ポーリング／WebSocket／プッシュ通知）。
- 想定規模（同時ユーザー数・タスク件数）の目安値と、それに基づくパフォーマンス数値目標。
